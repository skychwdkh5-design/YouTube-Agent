# Reference library

`sources.json` registers each reference video once (id, sha256 of the user's file, what it really is, limits). `effects/<ID>.json` holds one record per observed effect with: reference id, timestamp, description, visual purpose, animation behaviour, timing, estimated parameters, dependencies, implementation (module.symbol, checked by tests), status (IMPLEMENTED / PARTIAL / NOT_IMPLEMENTED), preset, compatible scene types, QA rules and the uncertainty. `VISUAL_REF_00x_*.md` are the human analyses; `UNIFIED_STYLE_GUIDE.md` merges the compatible techniques.

Add a reference: (1) add an entry to `sources.json` with the next id (VISUAL_REF_003...), never edit an old one; (2) write `effects/VISUAL_REF_003.json` and its analysis `.md`; (3) `python3 -m orbitalatlas.refs validate`; (4) update `UNIFIED_STYLE_GUIDE.md` only by adding, and note conflicts. The videos are third-party material and are not committed; use the sha256 to recognise them. Older analyses (`docs/references/REFERENCE_01_ANALYSIS.md`, `REFERENCE_02_ANALYSIS.md`, `VISUAL_EFFECT_CATALOG.md`, `ORBITALATLAS_REFERENCE_STYLE.md`) are different Shorts studied earlier and stay valid; ids VE-xx there and VR1-/VR2- here do not collide.
